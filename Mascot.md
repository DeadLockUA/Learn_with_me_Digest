# Mascot — "the duck"

The digest's recurring avatar. It appears in post images and moves from post
to post, asking questions or answering them. Agreed with the owner on
2026-11-11.

## Reference images

- Canonical look: [assets/images/mascot/duck-reference.png](assets/images/mascot/duck-reference.png)
  (asking pose, "?" hologram). Generated by `openai/gpt-image-2.5-sunburst`.
- Example in a scene: [assets/images/mascot/duck-example-answer.png](assets/images/mascot/duck-example-answer.png)
  (answering pose, check-mark hologram, generated from the reference).

## Character sheet

- Classic yellow rubber duck bath toy: smooth glossy vinyl, rounded body,
  flat bottom. **No legs, no feet, no arms** (small wing nubs are fine).
- Expressive face: large eyes with eyebrows and an orange beak that can open,
  so the duck can look curious, surprised or confident.
- Sleek modern AR glasses with a small cyan LED on the frame.
- The glasses project a glowing cyan holographic panel beside its head. The
  panel carries the duck's role in the post:
  - **asks**: a question mark, or a short question;
  - **answers**: a check mark, or a short answer.
- Lighting: warm and cozy on the duck and the scene (desk, plants, books, as
  in the site logo); cool cyan glow only from the hologram.
- Style: modern stylized 3D illustration.

## Role

- The duck stands in for the reader's question, or delivers the post's
  answer. Which one is chosen per post from the post's content.
- It is a listener and questioner (the rubber-duck debugging idea), not a
  lecturer.

## How to generate it

All three image models in `.env` accept the reference image through the
OpenRouter Image API (verified 2026-11-11):

```json
POST https://openrouter.ai/api/v1/images
{
  "model": "<model id from .env>",
  "prompt": "Use the attached reference image as the exact character design: the same yellow rubber duck with the same AR glasses. New scene: ... Avoid any logos or trademarked brand marks in the image.",
  "input_references": [
    { "type": "image_url", "image_url": { "url": "data:image/png;base64,<base64 of duck-reference.png>" } }
  ]
}
```

- `input_references` items must be objects; a plain string is rejected
  (HTTP 400, "expected object, received string").
- Always pass the reference image and include the character sheet above;
  text alone lets the look drift between models.
- Keep the closing no-logos instruction.

## How to animate it

Used for the site-wide duck facts widget (owner, 2026-11-12). Tooling:
[tools/duck/gen_clip.py](tools/duck/gen_clip.py) and
[tools/duck/process_clip.sh](tools/duck/process_clip.sh).

- Start frame: the duck on a plain off-white background (`#fdfdfd`), made
  from the reference image with an image model (`gen_clip.py frame`). Image
  models may return WebP under any file name, so convert it to a real PNG
  before you send it to a video model (Veo rejects a mislabelled file).
- Video: OpenRouter `POST /api/v1/videos` (async: submit, poll, download).
  Pass the start frame as both `first_frame` and `last_frame` in
  `frame_images`, so every clip begins and ends on the same calm pose and
  loops without a seam.
- Model: `google/veo-3.1-fast` (`OPENROUTER_VIDEO_MODEL` in `.env`), chosen
  by the owner on 2026-11-12 after an idle-clip comparison of 7 models. It
  supports 16:9 only; `process_clip.sh` crops the center to a square.
- In the `surprised` and `laughing` clips the duck shows small feet when it
  hops. The owner accepted this on 2026-11-12, so it is an allowed exception
  to "no feet" for animation only.
- Video generation is expensive. Never re-run it without the owner's
  go-ahead.
