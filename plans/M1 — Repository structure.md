# M1 — Repository structure

Goal: resolve AGENTS.md §8 ("no content structure finalized") — decide and
implement the entries folder layout before real drafting starts. Per §8,
structure is proposed to the owner, not invented unilaterally.

## Tasks

1. **Draft layout options** for one digest entry (blog file, LinkedIn file,
   image, metadata) — e.g. per-entry folder vs. flat files with shared naming
   convention. Include naming scheme (date? slug? topic tag?) since entries
   must show topic continuity (AGENTS.md §2).
2. **Check Jekyll constraints** — `_posts` naming/date requirements, where
   non-post assets (LinkedIn text, images) can live without breaking the
   Jekyll build.
3. **Present options to owner** with a recommendation (benefits/drawbacks
   per BEHAVIOUR.md) — get an explicit decision, not just discussion.
4. **Write the decision back** into AGENTS.md §8 (per AGENTS.md §7, "resolved"
   means written into the relevant doc, not just agreed verbally).
5. **Scaffold the structure** in the repo (empty folders/templates as needed)
   so Editor/Publisher have a fixed target from M4 onward.
6. **Update HLD.md** "Repo entries folder" data store description if the
   chosen layout differs from what's implied there.

## Gate

Do not start M2 (Jekyll skeleton) content wiring or M4 (agent roster) file
paths until this decision is written into AGENTS.md §8.
